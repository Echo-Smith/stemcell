# 个人作品集网站框架说明

## 1. 网站定位

网站类型：个人作品集 / 求职向 Portfolio

目标岗位：

- AI 产品专员
- AIGC 工具产品
- AI 应用产品
- 内容产品 / 内容效率工具

核心人设：

> 从内容运营一线出发，能够发现真实业务痛点，并独立设计、开发、上线 AI 应用产品的人。

核心优势表达：

> 真实内容工作场景 -> 发现效率痛点 -> 设计 AI 工作流 -> 接入模型能力 -> 做出 Demo -> 部署上线 -> 获得真实用户与数据反馈。

视觉气质建议：

- 清爽、专业、可信
- 有一定科技感，但不要过度炫技
- 重点突出项目成果、真实上线能力和产品思考
- 页面应服务于 HR 快速判断和面试官深入了解

## 6. 笔润智谈项目详情页填充建议

### 项目背景

内容创作者在热点评论、城市民生内容和栏目写作中，经常需要快速完成选题判断、资料补充、风格对齐、事实核查和查重改写。传统流程依赖人工搜索、人工整理和反复修改，效率较低。

### 用户痛点

- 热点多而杂，难以快速判断哪些选题适合写
- 资料分散，需要在多个平台搜索和整理
- 栏目风格难以稳定复现
- 事实核查耗时，容易遗漏关键证据
- 查重和改写是高频但机械的工作

### 产品方案

```text
热搜发现 -> 选题推荐 -> 知识库检索 -> 联网补充 -> 写作 / 润色 -> 事实核查 -> 查重改写
```

### AI 能力设计

- RAG：用于栏目规范、已录用文章和参考资料召回
- 实时搜索：用于补充最新资料和事实核查证据
- Prompt 模板：用于约束输出结构和写作风格
- SSE 流式输出：提升写作生成体验
- 事实核查链路：提取可验证声明并输出核查结果
- 文档解析与 OCR：支持 txt / md / docx / pdf 和图片内容处理

### 成果

- 查重功能快速上线后带来 200+ 访问量
- 当日调用量 1000+
- 31 个 Node Test 测试用例通过
- 3 位真实用户测试
- 7 篇经工具优化后的文章已录用

## 7. 贝伴项目详情页填充建议

### 项目背景

数字服务订阅越来越多，用户容易忘记续费时间、忽略自动扣费，也很难判断某项服务是否真的被充分使用。手动维护订阅信息又比较麻烦，因此需要一个更低成本的订阅管理工具。

### 用户痛点

- 订阅分散在不同平台
- 自动续费容易遗忘
- 权益是否被使用不透明
- 手动录入订阅信息成本高
- 低频工具容易被用户遗忘

### 产品方案

```text
订阅录入 -> 分类管理 -> 支出统计 -> 预算提醒 -> 权益管理 -> AI 助手建议
```

### AI 能力设计

- Function Calling：支持自然语言新增、修改、删除订阅
- OCR：从订阅 / 支付截图中提取服务名、价格、周期和续费日期
- 本地知识库：为订阅服务补全和 AI 问答提供上下文
- 对话记忆：沉淀用户偏好和长期管理习惯

### 成果

- 完成 PWA 产品上线
- 实现账号体系、订阅 CRUD、操作日志和支出统计
- 支持体验账号、登录认证、数据导入导出
- 形成订阅健康分、等级成就、支出分享和好价搜索等留存设计

## 8. CareerTrace / 职迹AI 项目详情页填充建议

### 项目背景

求职材料往往在投递前临时整理，但真实经历、项目细节、成果数据和面试反馈应该长期沉淀。CareerTrace 的核心想法是将职业材料作为长期资产管理，而不是一次性生成简历。

### 用户痛点

- 经历和项目材料分散，临时写简历容易遗漏
- 不同 JD 需要不同表达重点
- 面试准备缺少针对性反馈
- 简历修改和面试反馈之间没有沉淀闭环

### 产品方案

```text
简历解析 -> 职业材料库 -> JD 分析 -> 岗位匹配 -> 定制简历 -> AI 模拟面试 -> 反馈回流
```

### 当前状态

- 已完成产品规划
- 已设计核心信息架构
- 已搭建 Flutter 移动端原型
- 已搭建 FastAPI 后端骨架

### 展示重点

- 信息架构图
- 功能流程图
- Flutter 原型截图
- 产品路线图
- 对求职场景的长期思考

候选人背景：2024 届新媒体技术本科，目前从事新媒体运营，服务过 40 万粉丝级官方账号，有单条内容 10 万+ 阅读/播放案例。已独立上线两款 AI 应用：「笔润智谈」AI 写作工作流工具和「贝伴」AI 订阅管理助手，实践过 RAG、OCR、事实核查、Function Calling、SSE 流式输出、Node.js、Express、SQLite、Docker 部署等能力。
