### 路线 1：离线批量导出与恢复：最小验证路线

用 Python 标准库 + zipfile 实现一键导出为 zip（含 Markdown 与附件目录），恢复时解压到新目录，全程只读源笔记，优先验证核心流程，暂不做增量、校验和 GUI。

**交付范围**

- 批量导出：将指定根目录下的 .md 文件与附件目录（如 assets/）打包为 zip
- 恢复：将 zip 解压到用户指定的新目录，不触碰原笔记目录
- 命令行界面：两条命令 export 和 restore，带必要参数
- 基础日志：记录导出/恢复的文件数量和路径，便于人工核对

**明确舍弃**

- 增量导出（只导出变更文件）
- 加密、压缩选项、断点续传
- 图形界面（GUI）
- 校验和（如 SHA256）验证完整性
- 自动处理重名冲突（恢复时若目标已存在则直接报错，不覆盖）

**执行步骤**

- 用 Python 标准库（os, zipfile, argparse）编写 export.py：遍历源根目录，收集 .md 文件和附件目录（如 assets/ 或 attachments/，可在参数中指定），写入 zip，保持相对路径；源文件仅以只读方式打开，绝不写入或删除。
- 编写 restore.py：读取 zip，逐个解压到目标目录（目标必须为空或不存在，否则报错退出），确保不覆盖任何已有文件，且不写入源目录。
- 在本地用一个小测试笔记目录（含 .md 和附件）运行 export 和 restore，人工对比恢复后的文件内容与原始文件（可用 diff 命令），验证“不修改原始笔记”约束。
- 记录附件规模（文件数量和总大小），为后续优化提供依据；当前版本不做性能优化。

**风险**

- 附件目录结构不统一（如多级嵌套、多种命名），导出时可能漏掉部分附件；需在参数中明确附件目录名或采用“全部非 .md 文件”策略。
- 恢复时若目标目录非空，可能误覆盖用户其他文件；已通过强制要求目标目录为空来规避，但需在文档中强调。
- zip 文件名或路径包含非 UTF-8 字符时可能出现编码问题；若遇到，需在代码中处理或先人工重命名。

**代价**

- 放弃增量导出和校验，换取最快实现和最少维护（代码量小，依赖少）。
- 放弃 GUI，使用命令行，换取开发时间短，且对个人用户足够。
- 放弃自动重名处理，换取恢复安全性（绝不覆盖），代价是用户需手动清理目标目录。

**适用条件**

- 需要在一两天内获得可用的导出/恢复功能，且能接受命令行操作。
- 附件规模不大，单次全量导出时间可接受（几分钟内）。
- 个人笔记目录结构相对简单，附件目录可明确指定。

**工作量估计：** 0.5-1 人日（含测试）

估计依据：假设附件规模在几千个文件以内，单次导出时间可接受；使用 Python 标准库，无需额外依赖；开发者熟悉 Python 基础。

**核对：** 模型未发现冲突（未实测）。候选方案清晰，覆盖所有硬约束。风险点在于附件目录结构不统一可能导致漏附件，以及恢复时目标目录必须为空，但已通过强制要求规避。软分数中可执行性高，取舍清晰，风险控制中等。

- C1 / pass：候选明确使用 Python 标准库，无网络依赖，满足离线运行要求。；候选证据：用 Python 标准库（os, zipfile, argparse）编写 export.py
- C2 / pass：候选明确声明源文件只读，且恢复时解压到新目录，不触碰原笔记目录，满足不得修改或删除原始笔记。；候选证据：源文件仅以只读方式打开，绝不写入或删除。

### 路线 2：最小维护批量导出与恢复方案

采用纯文件复制与zip打包的离线方案，不引入数据库或额外服务，导出与恢复均通过文件系统操作完成，以降低长期维护成本。

**交付范围**

- 提供命令行工具，将指定笔记根目录下的所有Markdown文件及附件目录复制到临时目录，并打包为zip文件
- 提供恢复命令，将zip包解压到用户指定的目标目录，仅新增或覆盖目标目录中的文件，不删除目标目录任何现有文件
- 支持校验：导出时生成文件清单与校验和，恢复时可选校验，确保不修改原始笔记

**明确舍弃**

- 不做增量导出、压缩加密、云同步或远程备份
- 不做图形界面，仅提供命令行接口
- 不处理Markdown内部链接重写或附件路径映射
- 不处理非Markdown文件或非附件目录的其他类型文件

**执行步骤**

- 在笔记根目录下创建导出脚本（如export.sh），使用find和zip命令收集.md文件及附件目录，复制到临时目录后打包
- 在笔记根目录下创建恢复脚本（如restore.sh），使用unzip解压到指定目标目录，并使用cp --no-clobber避免覆盖已有文件
- 在导出时生成文件清单（sha256sum）保存到zip内，恢复时可选执行校验

**风险**

- 附件目录结构复杂或存在符号链接时，zip可能无法完全保留元数据
- 恢复时若目标目录已有同名文件，默认不覆盖可能导致用户误以为恢复失败
- 未测试大附件（如超过10GB）时，zip性能和磁盘空间可能不足

**代价**

- 为降低维护成本，牺牲了增量备份和自动定期备份的便利性
- 为保持简单，牺牲了跨平台兼容性（仅限Unix-like环境）
- 为不引入依赖，牺牲了加密和压缩选项的灵活性

**适用条件**

- 笔记规模不大，且手动执行导出恢复可以接受
- 开发者熟悉命令行工具，且主要使用Linux/macOS环境
- 对备份频率和自动化要求低，优先保证稳定和零依赖

**工作量估计：** 1-2天

估计依据：假设开发者熟悉shell脚本和zip/unzip命令，且笔记规模在万级文件以内

**核对：** 有约束待核实。方案整体符合硬约束，但存在一些待验证事实：未明确说明导出时是否修改原始笔记（如生成临时文件的位置），但基于描述推断为不修改；恢复时默认不覆盖可能导致用户误判，但未违反硬约束。风险点包括附件目录复杂结构、大附件性能等，但未影响硬约束。

- C1 / pass：候选方案明确为离线操作，不依赖网络或外部服务，符合必须离线运行的硬约束。；候选证据：采用纯文件复制与zip打包的离线方案，不引入数据库或额外服务
- C2 / unknown：模型未提供可核对的候选原文证据；候选证据：恢复时若目标目录已有同名文件，默认不覆盖可能导致用户误以为恢复失败；恢复命令...仅新增或覆盖目标目录中的文件，不删除目标目录任何现有文件
- C3 / pass：候选方案明确只处理Markdown文件和附件目录，不处理其他类型文件，符合第一版只支持Markdown和附件目录的硬约束。；候选证据：提供命令行工具，将指定笔记根目录下的所有Markdown文件及附件目录复制到临时目录，并打包为zip文件

### 路线 3：基于目录快照的批量导出与恢复（含长期扩展预留）

将笔记库视为只读源，通过生成目录快照清单（文件路径、哈希、大小）实现导出与恢复。导出时复制文件到目标目录并生成清单；恢复时依据清单校验并复制回原位置，全程不修改原始笔记。预留插件接口以支持未来格式（如 PDF、图片）和存储后端（如加密压缩包）。

**交付范围**

- 导出：扫描指定根目录，复制所有 .md 文件和附件目录（如 assets/）到导出目标，生成 manifest.json（含相对路径、SHA-256、大小）
- 恢复：读取 manifest.json，校验文件哈希后复制回原相对路径；若目标存在同名文件则跳过并报告，不覆盖
- 提供命令行工具（如 note-export）和简单配置文件（如 .note-export.yaml）

**明确舍弃**

- 不支持非 Markdown 笔记（如 PDF、图片作为笔记主体）
- 不支持增量导出或增量恢复（第一版全量）
- 不支持加密、压缩、云同步或 GUI
- 不提供删除原始笔记或导出目录的能力

**执行步骤**

- 设计核心接口：定义 NoteSource（扫描、读取）和 NoteSink（写入导出/恢复目标），确保所有操作通过接口，便于未来扩展
- 实现导出流程：遍历源目录，收集 .md 和附件目录文件，计算哈希，复制到导出目录，生成 manifest.json
- 实现恢复流程：读取 manifest，校验导出文件哈希，若原位置文件不存在或哈希不同则复制；若存在且哈希一致则跳过；若存在但哈希不同则记录冲突并跳过
- 编写测试：创建临时笔记库，执行导出和恢复，验证原始文件未被修改（比对哈希）
- 文档化：记录使用方式、配置项和扩展点（如何添加新格式或存储后端）

**风险**

- 附件目录结构复杂（嵌套、符号链接）可能导致扫描遗漏或误复制
- 恢复时冲突处理不当可能覆盖用户现有文件（需严格校验哈希）
- 未来扩展格式时，现有清单结构可能不兼容，需预留版本字段

**代价**

- 采用全量快照而非增量，换取实现简单和低维护
- 预留插件接口增加少量初期设计成本，但避免未来重构
- 不提供压缩/加密，减少依赖和复杂度

**适用条件**

- 笔记库规模不大（<10GB），导出频率低
- 开发者熟悉脚本语言，可接受命令行操作
- 未来可能增加新格式，但不确定具体需求，希望保留扩展点

**工作量估计：** 约 3-5 天（一人全职）

估计依据：假设笔记库结构简单（根目录下 .md 和 assets/），开发环境已有 Node.js 或 Python；不包含 UI 和复杂错误处理

**核对：** 模型未发现冲突（未实测）。候选方案在功能设计上完整覆盖了所有硬约束，并提供了清晰的实现步骤和风险控制。但存在一些待验证事实：实际附件规模未知，可能影响性能；恢复冲突处理策略（跳过而非覆盖）虽保守但可能不满足用户期望；插件接口预留增加了初期设计成本，但符合减少后续维护的偏好。整体方案可行，风险可控。

- C1 / pass：候选方案描述为本地命令行工具，未涉及网络或在线服务，且所有操作均在本地文件系统进行，符合离线运行要求。；候选证据：导出：扫描指定根目录，复制所有 .md 文件和附件目录（如 assets/）到导出目标，生成 manifest.json（含相对路径、SHA-256、大小）
- C2 / pass：候选明确说明恢复时不覆盖同名文件，且导出流程仅复制文件，不包含删除或修改原始笔记的操作，符合不得修改或删除原始笔记的约束。；候选证据：恢复：读取 manifest.json，校验文件哈希后复制回原相对路径；若目标存在同名文件则跳过并报告，不覆盖
