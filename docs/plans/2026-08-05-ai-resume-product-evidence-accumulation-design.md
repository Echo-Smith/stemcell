# AI Resume Assistant：产品经验积累模块设计

## 目标

把 `ai-resume-assistant` 从“投递前整理既有事实”扩展为“在真实项目进行中持续生产、分级和保存产品证据”，避免把 AI Demo、功能完成或使用人数直接写成产品价值。

## 方案选择

采用“主 skill 路由 + 单独 reference”结构：

- 在 `SKILL.md` 增加 `Accumulation mode`、触发条件、硬规则和输出格式；
- 在 `references/product-evidence-accumulation.md` 保存产品决策台账、结果层级、Vibe Coding 完整性检查和 30 天证据计划模板；
- 更新 `agents/openai.yaml`，让界面提示覆盖“积累产品证据”场景。

没有采用的方案：

- 全部写入 `SKILL.md`：使用直接，但会让所有简历任务承担无关上下文成本；
- 拆成独立 skill：边界更清楚，但会割裂事实台账、简历叙事和长期积累，且不符合本次“加入现有 skill”的要求。

## 四个模块

1. **产品决策台账**：记录用户、场景、原有做法、问题证据、为什么现在、候选方案、非目标、第一版假设、指标、结果、反馈、取舍和下一步。
2. **结果层级识别**：区分功能完成、使用规模、重复使用、用户结果和业务结果，简历只能使用实际达到且可归因的层级。
3. **Vibe Coding 完整性检查**：用用户、场景、原有方案、优先级、第一版边界、验证方法和实际结果七个问题区分 Demo、工程证据与产品闭环。
4. **缺口到行动计划**：把“缺指标”转成一个真实项目上的 30 天取证计划，明确假设、观察方法、护栏、时间点和证据载体。

## 验证

- 运行 skill creator 的 `quick_validate.py`；
- 检查主文件行数与引用路径；
- 用三个典型请求做静态路由检查：简历审计、正在做项目的证据沉淀、只有 Demo 的 Vibe Coding 项目判断；
- 同步工作区源与当前已安装副本后比较文件一致性。
