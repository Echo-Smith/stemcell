# Agent 编辑部演示页设计说明

## 目标与事实边界

为“AI Memory & Agent｜模型应用产品经理”定向简历补充一份本地可运行、可点击的面试演示页。页面只引用当前简历与《笔润智谈 V2 架构实现核验》中已经确认的产品机制和数据；交互中的任务内容明确标记为“机制演示样例”，不伪装为线上日志、线上实验或用户结果。

页面需要让招聘方在数分钟内亲手验证三个判断：研究、写作、审校 Agent 不是并排展示，而是通过版本化交付物和动态质量路由协作；四层 Memory 有不同作用域和治理字段；Decision Packet 会把建议、依据、不确定性与批准后果交还给人类，并支持批准、退回、接管。

## 方案选择

采用“单场景编辑部调度台”，不做完整后台或长篇案例站。桌面端以窄侧轨、Agent 接力区和横跨式 Decision Packet 组成不对称布局；移动端转换为纵向任务流。用户先运行一次机制演示，再查看四层 Memory，最后选择人工决策路径。

## 视觉规格

- 方向：Industrial / utilitarian，参考编辑部值班台、校样纸和稿件流转章。
- 色板：Ink #151714、Paper #F1EFE7、Signal Orange #E05A33、Memory Moss #69735B、Proof White #FBFAF5。
- 字体：中文使用 Noto Serif SC / Source Han Serif SC，标签与数据使用 IBM Plex Mono，并提供离线本地回退。
- 网格：桌面 12 栏，左侧值班轨占 2 栏，主流程占 10 栏；Decision Packet 横跨主流程并略微错位，形成“压在稿件上的校样单”。
- 动效：只保留一次 Agent 接力状态变化和 Decision Packet 进入；尊重 prefers-reduced-motion。

## 交互与状态

1. “运行协作流”依次点亮研究、写作、审校 Agent，生成研究简报、初稿和审校报告三类版本化交付物。
2. 四个 Memory 入口展示各自机制与对当前任务的作用，并同时显示用户、来源、适用范围、置信度、生命周期等治理字段。
3. Decision Packet 支持：
   - 批准：进入待发布，记录人工批准。
   - 退回：回到写作 Agent，产生修订稿状态并保留退回原因。
   - 接管：暂停 Agent，将当前责任人切换为用户，开放本地文本编辑区。
4. “重置演示”恢复初始状态。

## 验证

- 静态检查：HTML 结构、JavaScript 语法、CSS 禁用色与字体审计。
- 运行检查：本地 HTTP 服务打开页面；逐一验证运行协作流、四层 Memory、批准、退回、接管、重置。
- 响应式检查：桌面与移动视口无横向溢出，键盘焦点可见，减少动效设置生效。
