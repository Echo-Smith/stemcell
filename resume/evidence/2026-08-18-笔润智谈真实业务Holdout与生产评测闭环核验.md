## 二、已核验事实

### 1. 离线策略选择已经完成

- 已构建 80 对策略实验：开发集 48 对、Holdout 32 对，共 160 个输出。
- 采用单变量比较，分别验证来源证据闸门与结构化个人风格 Memory。
- 策略 Holdout 延续开发集方向：来源证据闸门保留；个人风格 Memory 没有改善结果，因此保持默认关闭。
- 候选策略固定为：`sourceEvidenceGateEnabled=true`、`memoryOptIn=false`。

边界：离线用例主要用于策略回归和异常边界验证，不能单独代表真实用户任务效果。

### 2. 建立 20 条真实业务 Holdout

- 从线上 `trafficType=user` Trace 中采集 21 条，按输入指纹去重 1 条，最终冻结 20 条。
- 20 条均完成来源反查、机器脱敏预检与人工脱敏确认；合成补数为 0。
- 冻结文件记录数据集版本、候选策略、来源 Trace 哈希和脱敏文本哈希，私有正文未进入 Git。

证据状态：代码、冻结清单和发布记录核验通过。

### 3. 候选版本重放暴露发布风险

当前最终机械报告记录：

- 20 条真实业务任务全部完成请求重放；
- 5 条出现请求级硬失败，硬失败率 25%；
- 平均延迟约 71.0 秒，P50 约 65.5 秒，P95 约 107.1 秒；
- 工具失败 5 次；
- provider 未返回逐请求 Token / 成本，明确标记为不可用，而不是按零成本处理。

这组数据不适合用于宣传性能，但能证明评测真正参与发布决策：候选版本没有因为离线实验表现较好而直接放行。

### 4. 人工业务评审已经完成，但需区分标签性质

- 20 条均有人工评审记录；评审角色为业务评审，方式为独立盲评。
- 评审结果分布：7 条 `light_edit`、6 条 `heavy_edit`、7 条 `reject`，无 `direct_use`；平均修改负担记录为 0.483。
- 评审根因初判分布：模型 8 条、检索 7 条、输入 5 条。

这些数据只能称为“人工业务评审”或“评审接受代理”，不能称为真实用户接受率。当前没有可靠的最终编辑量和真实使用行为闭环。

### 5. 已补充生产观测与用户结果事件

- P0 健康接口可按真实用户流量聚合硬失败、知识库路由、语义接受代理、延迟和成本可用性。
- P1 采用独立事件流记录复制、下载、二次生成、继续编辑与显式接受 / 拒绝，不保存用户输入、编辑后正文、剪贴板内容或自由反馈文本。
- 截至 2026-08-18 本次核验，线上健康接口仅有 1 条 `user` 样本，结果事件为 0，因此尚不足以形成真实行为接受率。

### 6. Lexiang-only 上线后专项 Smoke

- 2026-08-18 最新报告覆盖 24 个明确要求仅使用乐享知识库的场景。
- 24/24 路由到 Lexiang，24/24 识别为 knowledge-only，未记录 websearch 误触发或机械硬失败。
- 平均延迟约 52.7 秒，最长约 119.1 秒；尚无人工内容质量评审和真实用户行为结果。

该结果可以证明知识库路由契约在这批专项 Smoke 中可执行，不能写成“线上误触发率永久为 0”或“内容质量 100% 通过”。

## 三、重要审计问题

### High：机械运行与人工评审不是严格同一轮输出

- 最终机械汇总的 Run 为 `real_business_candidate_frozen_v1_with_output`。
- 人工评审记录的 Run 为 `real_business_candidate_frozen_v1`。
- 评审包在主运行没有正文时会读取 retry diagnostic 输出；汇总脚本按 `holdoutId` 合并评审，没有校验 `review.runId` 是否等于机械报告 Run。
- 逐条检查发现 7 条机械硬失败与人工 `hardFailures` 标记不一致。

影响：人工评分对诊断仍有价值，但 35% 不能作为“同一候选版本的接受率”进入简历、作品集或线上效果报告。

修复建议：评审记录必须同时绑定 `outputSourceRunId` 与输出哈希；汇总时拒绝跨 Run 合并。重试输出应单独标记为“恢复后内容质量”，不能覆盖首次失败的发布指标。

### High：真实行为结果尚未形成

- 当前人工评审不能替代真实用户最终使用、复制、下载、继续编辑或显式反馈。
- P1 埋点已经实现，但当前可见结果事件为 0。

影响：只能证明“具备采集能力”，不能证明用户接受、修改负担改善、留存或业务增长。

### Medium：样本与评审代表性有限

- 真实业务 Holdout 为 20 条，且目前只看到一名业务评审者。
- 样本可以用于发现高风险问题和阻断发布，不足以估计稳定线上比例。

### Medium：成本与延迟仍未闭环

- provider usage 不可得，无法判断质量提升是否以不可接受成本换取。
- P50 与 P95 延迟较高，虽然已经增加 SSE 心跳和客户端超时治理，但尚无新一轮同口径真实任务数据证明改善。
