## 一、证据边界

- 会议记录能够证明面试官的提问顺序和候选人的主要回答，但不是逐字稿。
- “明显卡壳”“把锅甩给底层”“打补丁式迭代”等属于会议助手的生成式评论，不视为面试官原话或淘汰理由。
- “未通过”是用户确认结果；具体评价和决策权重未知，因此本复盘只能依据提问路径推断能力缺口。
- 项目名称统一为“笔润智谈”。

## 二、结论

本次面试证明候选人具备真实业务场景、Agent 搭建、Badcase 分层和 Prompt 小步回归能力，但没有充分证明能够独立承担生产级 Agent 效果策略。ReAct 原理未答出是直接失分项，更深层的差距来自：效果定义不稳定、评测集与 Rubric 尚未形成真实业务闭环、策略修改缺少量化前后对照，以及跨产品 / 算法 / 工程协同经验不足。

可将当前能力定位为：

> 业务型 AI 产品 Builder，能从内容生产问题出发完成 Agent 工作流并处理真实反馈；已具备效果策略意识，生产级 Eval、策略实验和团队化落地仍需补齐。

## 四、已经证明的能力

### 1. 能从真实业务问题出发构建产品

不是为了使用 Agent 而找场景，而是针对作者选题困难、构思成本和稿件质量不稳定，覆盖选题、来源获取、写作、润色、查重与校正流程。

### 2. 具备可用的 Badcase 归因框架

能够区分：

- 资料缺失或过期：Context / 检索层；
- 字数、格式不符合：Prompt / 调用策略层；
- 风格不符合用户：Memory / 个性化层；
- 并发失败或工具不稳定：Tool / 系统运行层。

这比“看到坏结果就改 Prompt”更接近策略岗位。

### 3. Prompt 调优方法基本正确

已形成：

`复现 Badcase → 判断是否为 Prompt 根因 → 最小改动 → 回放原案例 → 检查正常样本副作用`

欠缺的是固定回归集、维度阈值和策略版本记录，而不是完全没有方法。

### 4. 个人探索出现真实组织采用

用户确认：笔润智谈中的“核查较真”能力被部门采纳，已从个人服务器拆分并部署至公司服务器。该事实能证明一项能力从个人探索进入内部使用，但不能表述为整个笔润智谈完成公司级部署，也不能推出使用规模或业务收益。

## 五、决定性缺口

### 1. 简历术语与口头掌握程度不一致

简历写有 ReAct，却无法解释其基本机制。策略岗位允许非工程背景，但凡进入简历的 Agent 概念，都应至少能回答：

`是什么 → 解决什么问题 → 项目中在哪里使用 → 为什么不用更简单方案 → 如何退出和兜底`

### 2. “有评测意识”尚未升级为“有评测体系”

当前真实工作流主要依靠人工评估事实真实性、信息完整度、写作质量、响应性和时效性。代码中存在规则评分、Judge、Trace 等结构，不等于真实业务已经形成：

- 分层评测集；
- 明确 Rubric 与分数锚点；
- 人工金标；
- 标注一致性；
- LLM-as-Judge 校准；
- 策略版本前后对比；
- 发布门禁、灰度和线上回流。

以后必须明确回答“已经做到哪里”和“如果入职会如何补齐”，不能混为同一成熟度。

### 3. 业务指标使用不严谨

产品目标可以是提高投稿完成效率和稿件适配度，但目前没有投稿分母或使用前基线，因此不能说“提升投稿成功率”。当前可用结果为：

- 2026 年 5—8 月，14 位作者借助产品完成 28 篇获栏目刊发稿件；
- 单个用户最高使用 20 余次；
- 200+ 为体验补充规模。

### 4. 检索策略缺少明确停止与降级条件

“慢接口直接丢弃”会引出完整性风险。需要补充：来源优先级、最少独立信源、关键事实覆盖、冲突处理、搜索停止条件，以及资料不足时停止成稿或转人工的策略。

### 5. 缺少生产型跨团队案例

个人项目证明端到端执行，不能替代正式团队中的指标对齐、接口边界、排期、实验评审、上线灰度和责任分配。后续回答应诚实承认正式经验不足，并用内部系统验收、内容协同和双人项目证明可迁移能力。

## 六、对旧准备库的修正

旧准备稿可以继续保留为历史材料，但以下口径需要停用：

1. 不再以 V1 / V2 作为项目讲述主线；直接讲问题、产品功能、策略变化和结果。
2. 不把代码中实现的评测结构说成当前真实业务已经运行的自动化 Eval Loop。
3. 不使用“提升投稿成功率”，改为“辅助作者完成真实投稿任务”。
4. 不以 53 名完成写作任务作为首要结果；统一以最新确认的 14 位作者、28 篇获刊发稿件和单用户 20 余次为主，200+ 为补充覆盖。
5. 不泛称“产品被公司采用”；准确表述为“核查较真能力被部门采纳并拆分部署”。
6. 所有 ReAct、Memory、RAG、LLM-as-Judge 等术语必须配套原理、项目映射和边界。

## 七、下一阶段面试目标

下一次同类面试需要让面试官在 30 分钟内形成四个确定判断：

1. 候选人能用业务语言说明 Agent 原理与取舍；
2. 候选人清楚当前评测体系尚未生产化，但能设计正确的补齐路径；
3. 候选人能完整讲出至少三条 Badcase 策略闭环；
4. 候选人能够作为效果 Owner 与产品、算法、工程和人工评审者共同推进，而不是只会独立搭建。
