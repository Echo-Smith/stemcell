## 三、十个技术一句话

1. **Agent：**围绕目标维护状态、决定行动、调用工具并按条件退出的系统。
2. **ReAct：**Reasoning 与 Acting 交替，模型根据工具观察动态决定下一步。
3. **Pipeline：**预先固定关键步骤，适合流程稳定、错误成本高的任务。
4. **Tool Use：**模型发出结构化调用，系统校验参数、执行工具并返回结果。
5. **RAG：**先检索外部材料再生成；能补充知识和来源，但不能保证材料真实相关。
6. **Context Engineering：**管理模型看到哪些指令、资料、状态和工具结果，而不只是改 Prompt。
7. **Memory：**将筛选后的状态或偏好跨任务保存和召回，需要作用域、冲突、过期和删除机制。
8. **Eval：**用固定样本、Rubric 和运行过程比较策略效果，而不是看一次漂亮输出。
9. **LLM-as-Judge：**让模型按 Rubric 批量评价语义质量，但要防长度、自偏好、位置和尺度偏差。
10. **Regression：**策略修改后回放原 Badcase、相邻场景和正常样本，确认修复且没有副作用。

## 四、三条核心取舍

### Pipeline vs ReAct

> 核查、审校和人工确认用固定 Pipeline；资料不足时选择搜索工具可用 ReAct。确定性和错误成本决定方案。

### Prompt vs Memory

> 全体用户共享的规则写 Prompt；个人长期偏好进入用户级 Memory；一次性要求只保留在当前 Context。

### 人评 vs 机评

> 规则判断确定性指标，Judge 做语义初评，人工制定标准、处理高风险和分歧并校准机器。

## 五、三个 Badcase

### 模板化表达

`逻辑改善但不像本人 → 归因全局 Prompt 与个人偏好混用 → 拆分通用规范和用户级 Memory → 原案例及正常样本回归 → 暂无量化前后差异`

### 资料缺失 / 过期

`成稿缺关键材料 → 检查 query、来源、时效和过滤 → 调整来源优先级与分层补查 → 资料不足则停写或转人工 → 比较可用材料率与延迟`

### 批量查重失败

`任务失败 → 归因并发和工具层 → 队列、超时、失败兜底与事实保护 → 30 余次真实批量任务；曾单次 1500+ 条、5 分钟内返回`

## 六、当前评测成熟度

标准回答：

> 当前真实工作流以人工评估为主，代码中有规则评分、Judge、Trace 和版本比较的离线结构，但尚未完成生产级人工金标、发布门禁和在线 A/B。准确定位是有评测实践和离线原型，不是成熟自动化 Eval 平台。

搭建 Eval 的顺序：

`任务分层 → 真实 / 边界样本 → Rubric 与硬门槛 → 人工金标 → Judge 校准 → 固定回归集 → 发布门禁 → 灰度 → 线上 Badcase 回流`

## 七、检索策略

- 1—3 个 query；常规总素材约 8—10 条；
- 用户材料 P0，知识库 / 讨论 P1，新闻与实时语境 P2，模型常识 P3；
- 去重后按相关性、信息价值、来源质量和时间排序；
- strong / medium / weak / conflict 分层；
- 关键事实仍缺失：补查、追问或转人工，不假装资料充分；
- 慢源只在非关键且已有替代来源时降级丢弃。

## 八、五条事实边界

1. 14 位作者、28 篇获刊发稿件、单用户最高 20 余次；200+ 是补充体验规模。
2. 不说“提升投稿成功率”，因为没有投稿分母和可比基线。
3. 部门采用的是“核查较真”能力，不是整个产品。
4. 当前真实质量判断以人工为主，离线代码结构不等于生产 Eval。
5. 正式工作不是 AI 产品岗位，跨职能 AI 团队经验有限。

## 九、岗位理解

> Agent 策略产品运营要对效果闭环负责：和产品定义用户任务与指标，把好坏转成评测集和 Rubric，和 Prompt / 算法选择修复策略，和前后端建设 Trace、版本、灰度与回滚，再把线上 Badcase 回流为可复用策略资产。

## 十、面试前 15 分钟

1. 朗读 75 秒自我介绍两次；
2. 不看稿解释 ReAct、RAG、Memory、Eval；
3. 随机讲一个 Badcase，必须说到验证和边界；
4. 复述五条事实边界；
5. 选择三个反问问题。

## 十一、优先反问

1. 当前 Agent 的核心用户任务和主指标是什么？
2. 最大一类 Badcase 在 Prompt、Memory、Tool 还是评测标准？
3. 离线 Eval、人工评审和线上实验如何形成发布门禁？
4. 岗位能否接触脱敏 Trace、真实反馈和实验数据？
