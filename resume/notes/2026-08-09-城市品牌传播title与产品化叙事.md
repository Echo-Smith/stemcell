# 城市品牌传播 title 与产品化叙事

## 推荐 title

### 简历工作经历

**内容运营｜城市品牌传播与内容策略**

这是目前最准确的写法：保留正式岗位属性，同时让招聘者看到工作目标、策略性和可迁移能力。

### 市场化职能标签

- 城市品牌传播与内容策略运营
- 内容策略运营
- 内容产品运营（仅用于内容平台、创作者平台或内容工具岗位）

### 暂不建议使用

- 城市品牌产品经理
- 品牌产品经理
- 增长产品经理
- 商业化产品经理

原因：现有工作证明了内容供给、分发、协同和复盘能力，但尚未证明正式产品路线图、研发资源所有权、商业收入指标或增长实验所有权。产品化叙事可以说明能力迁移，不能替代任职事实。

## 将“城市整体形象”视为长期内容产品

这不是把城市包装成软件产品，而是用产品思维管理一个持续运营的品牌资产：

- **目标用户：**本地居民、城市关注者、内容传播参与者及不同平台受众。
- **核心价值：**以稳定、可信且具有城市辨识度的内容，持续建立城市认知和情感连接。
- **内容供给：**节庆节点、人文经济、城市故事、热点议题及多媒体素材。
- **分发渠道：**今日头条、微博、小红书和账号矩阵。
- **协作机制：**选题、约稿、审核、平台适配、任务分发、监测反馈与归档。
- **验证方式：**曝光、热点表现、稿件刊发、矩阵反馈、模拟演练和阶段复盘。
- **治理边界：**内容准确性、敏感信息、平台规则、发布时效和多方职责归属。

## 简历写作路径

优先使用：

`城市形象目标 → 内容主题与供给机制 → 平台分发策略 → 多方协同 → 数据反馈与复盘`

避免使用：

`完成上传 → 完成登记 → 完成推送 → 罗列数量`

数字用于说明规模或结果，不承担全部叙事。必须区分个人动作、团队产出、平台表现和业务影响。

## 2026-08-19 新增：从内容运营到业务流程产品化

当前工作已形成三类可迁移的产品证据，但仍保留“内容运营”正式 title：

1. **信息对象化：**将微博话题、刊发文章、作者、篇名与矩阵账号从分散记录转为可维护的数据对象。
2. **流程自动化：**使用飞书智能表格完成话题自动抓取与分类；将刊发文章同步至内部知识库，并按作者与篇名归档。
3. **数据决策：**使用 Python 与 WorkBuddy 处理 50+ 个万粉级矩阵账号的发帖量、阅读量与粉丝数据，建立账号分层和内容表现模型，支持选题、节奏与运营动作调整。

对外叙事应使用：

`人工登记 / 资料分散 / 重复拼表 → 定义对象与字段 → 自动采集和知识归档 → 形成可查询的数据资产 → 支持运营判断`

不要写成：

- “开发内容中台”——当前没有正式中台产品 ownership；
- “通过模型提升运营增长”——当前缺少增长归因与效果对照；
- “负责 50+ 个万粉账号增长”——当前事实是数据分析与建模覆盖范围，不是粉丝增长归因；
- “正式产品经理经验近 2 年”——近 2 年是内容运营正式经验，产品证据来自业务流程产品化与个人项目。
